# ADR 0002 — 不做键盘监听，不做任何按键采集

- 状态：已采纳
- 日期：2026-11-17

## 背景

实现「记录输入热词」最直觉的方案是 `CGEventTap` 或 `IOHIDManager` 监听键盘事件。

## 决定

**禁止。** 本项目的任何模块都不会：

- 注册 `CGEventTap`、`IOHIDManager`、`NSEvent` 全局监听；
- 读取输入法候选窗口内容；
- 截屏、OCR；
- 访问剪贴板。

## 理由

1. **信任成本 > 功能收益**。一个需要「辅助功能」授权、能看见所有按键的
   后台程序，其潜在危害远大于它带来的便利。任何人在审查代码前都不该被要求安装它。
2. **能力重叠**。原生输入法已经完成了「从按键到词条」的全部推断，
   再监听一遍键盘是把同一个结论算两次，还多担一份风险。
3. **可审计**。不监听键盘意味着本仓库的代码量小到可以在一小时内被人读完。

CI 里有一条守卫测试（`tests/test_safety.py`），对源码做字符串与 AST 断言，
把上述约束固化进构建。

### 修订（2026-11-17）：不要把 denylist 说成证明

初版这里写的是「能用 grep 证明没有敏感 API」，这个说法**不成立**：

- `subprocess.run(["osascript", ...])` 可以读剪贴板，源码里没有任何敏感 API 名字；
- `from socket import socket` 绕开 `socket.` 这个字符串；
- `ctypes` 可以动态调用任意框架函数，名字一个字都不出现；
- 测试只扫描 `src/imehot/`，新增子包或编译产物不在范围。

准确的说法是：**我们维护一份已知敏感 API 的 denylist 冒烟测试，
它负责挡住随手引入的写法；证明的责任在人工审查和代码规模上。**
